## 2. ★ v1에서 뒤집힌 것 — 중앙이 중앙이 아니다

v1은 좌우 50:50을 전제해 "중앙 3분할 비움"을 규칙으로 삼았습니다. 폐기합니다.

- 실제 분할선은 **가로 37.5% 지점**입니다
- **그 자리가 실물 철당간이 서는 갭**입니다
- 따라서 **소실점을 화면 정가운데(50%)에 두면 안 됩니다.** 우측 스크린 안쪽으로 밀려 엉뚱한 데 꽂힙니다

### 새 구도 규칙
1. **분할선(37.5%) 주변은 비운다** — 구조물·인물·핵심 오브젝트 금지. 실물 철당간이 그 자리를 채운다
2. **소실점은 37.5% 지점 또는 그보다 왼쪽**에 둔다. 실물 당간이 소실점을 완성하게 한다
3. **좌 37.5% 구역과 우 62.5% 구역이 각각 독립된 그림**으로 읽혀야 한다
4. 좌측은 2:1로 **가로로 길고 얕다** — 하늘·지면을 크게 못 담는다. 수평 요소 위주
5. 우측은 8:3으로 **더 넓고 더 얕다** — 파노라마에 가깝다

## 3. 기존 플레이트가 못 쓰이는 이유

21:9(2.333:1) 플레이트에서 새 창으로 잘라내면:

| | background-size | 원본 세로 사용률 |
|---|---|---|
| 좌 (37.5% 폭 → 2:1) | 266.667% | **44%** |
| 우 (62.5% 폭 → 8:3) | 160% | **55%** |

**아래 정렬이라 남는 건 바닥 띠뿐입니다.** 지붕·하늘·산이 전부 잘려나갑니다.
S5 용두사 마당으로 시뮬레이션한 결과, 좌측 스크린엔 흙바닥과 석등 밑동만 남았습니다.

즉 **해상도 문제가 아니라 구도 문제**입니다. 다시 만들어야 합니다.

## 5. 생성 경로 — 두 안

합성 4.267:1은 이미지·영상 모델의 최대 21:9(2.333:1)를 **크게 넘습니다.** 한 장으로 못 뽑습니다.

### A. 화면별 개별 생성
| | 생성 비율 | 후처리 |
|---|---|---|
| 좌 | **2:1** 직접 생성 | 없음 |
| 우 | **21:9** 생성 → 8:3으로 상하 트림 | 세로 12.5% 잘라냄 |

- 장점: 각 화면이 자기 프레임에 맞게 제대로 구성됨. 추가 도구 불필요
- 단점: **한 컷당 생성 2회**. 좌우가 별개 이미지라 지면선·광원을 프롬프트로 맞춰야 함

### B. 한 장 생성 후 가로 확장
21:9로 생성 → `images_expand`(아웃페인트)로 4.267:1까지 좌우 확장

- 장점: 좌우가 **하나의 연속된 그림**. 원래 기획 의도에 충실
- 단점: 확장 단계 추가(비용·시간), 확장부 품질이 본체보다 떨어질 수 있음

**권장: A.** 좌우 화면이 물리적으로 떨어져 있고 그 사이에 실물 당간이 서 있어서,
관객이 두 화면을 하나의 연속 이미지로 읽지 않습니다. 각 화면이 독립적으로 완결되는 편이 낫고,
생성 실패 시 한쪽만 다시 뽑으면 되므로 반복 비용도 낮습니다.

## 6. 확정값 (2026-09-10)

전체 캔버스 **5320 × 1600 = 3.325 : 1** — 절대 크기가 아니라 **비율만** 의미가 있습니다.
이 값에서 나머지가 딱 떨어집니다:

| 항목 | 값 | 도출 |
|---|---|---|
| **갭** | **200** | 5320 − 1920 − 3200 |
| **좌측 세로 오프셋** | **640** | 1600 − 960 (좌측 하단 = 캔버스 하단) |
| 좌측 위치 | x 0, y 640 | |
| 우측 위치 | x 2120, y 0 | |
| 분할선 중심 | 전체 폭의 **37.97%** | 실물 철당간 자리 |
| 좌측이 더 내려간 양 | **400px** | 좌 하단 1600 vs 우 하단 1200 |

### 렌더러 상수 (`build_web.py` 상단)
```python
GAP      = 200
OFFSET_L = 640
SCR = {"L": dict(w=1920, h=960,  x=0,        y=OFFSET_L),
       "R": dict(w=3200, h=1200, x=1920+GAP, y=0)}
```
수치가 바뀌면 이 두 상수만 고치면 크롭·CSS·프리뷰가 전부 따라갑니다.

## 7. 렌더러 동작 (구현 완료)

1. **실제 크롭 파일 생성** — 플레이트를 캔버스 폭에 맞춰 **아래 정렬**로 얹고,
   좌/우 스크린 영역을 잘라 `<이름>__L.jpg` · `<이름>__R.jpg` 로 저장합니다. CSS 눈속임이 아닙니다.
2. **실제 위치로 배치** — 두 화면을 캔버스 좌표 그대로 절대 배치. 우측이 위, 좌측이 640 아래.
   그 사이 갭에 실물 철당간 위치를 금색 선으로 표시합니다.
3. **원본 플레이트에 사용 영역 오버레이** — 빨강=좌측, 파랑=우측이 실제로 쓰는 부분.
4. **클릭하면 내려받기** — 플레이트를 클릭하면 원본, 각 화면을 클릭하면 그 화면 크롭이 받아집니다.

## 8. 구성 규칙 v5 — 컷당 3버전 체제로 확정 (2026-09-10)

### 세로는 반드시 29% 버려진다
모든 모델의 생성 상한이 **21:9(2.357:1)** 다. gpt-2의 3:1은 카탈로그에만 있고 실제로는 거부되며,
`images_expand` 아웃페인트도 21:9가 상한이다. **3.325:1을 직접 뽑을 방법은 없다.**
캔버스 폭에 맞추면 플레이트 높이가 2257px가 되고 캔버스는 1600px이므로 **657px(29%)가 버려진다.**

### ★ 아래 정렬을 폐기하고 위/아래로 나눈다 — `ALIGN_Y = 0.62`
아래 정렬(위 29%를 통째로 버림)은 좌측 스크린이 원본 **아래 42%만** 보게 만들어
전각 지붕이 전부 잘려나갔다. 버리는 양을 **위 62% / 아래 38%**로 나눈다.

| | 플레이트에서 보이는 세로 구간 |
|---|---|
| 좌측 스크린 | **46.4% ~ 88.9%** |
| 우측 파사드 | **18.0% ~ 71.2%** |
| 두 화면이 공유 | 46.4% ~ 71.2% (24.8%뿐) |

플레이트 바닥을 조금 버리는 건 싸다 — 대개 빈 마당·물이고, 광장 바닥은 어차피 별도 투사면이다.
`build_web.py` 상단 `ALIGN_Y` 하나만 고치면 크롭·프리뷰·오버레이가 전부 따라간다.

### 프롬프트 규칙 — 존 지시가 아니라 카메라 지시로
"상단 1/3은 버려진다" 같은 지시는 **쓰지 않는다.** 영상화용 소스라
프레임 안에서 잘린 그림이 나오면 못 쓴다. 대신 카메라로 말한다:

1. **가까운 것을 두지 않는다** — "no foreground object, no near building, nothing close to the lens".
   모델은 "large main hall on the left"라고 쓰면 반드시 화면을 채우는 히어로 건물을 그린다.
2. **높이를 %로 못 박는다** — "every roof ridge at 58% or lower, every base at about 72%,
   measured from the top of the frame". 존이 아니라 **지면선과 능선의 높이**로 지시한다.
3. **비유를 준다** — "a village seen from across a wide river", "a monastery seen from the
   opposite mountain". 수치만으로는 잘 안 먹고 비유가 들어가면 확률이 크게 오른다.
4. **온전함을 명시한다** — "every building is complete, with clear air above and below,
   none touching any frame edge".
5. **가로 연속** — "runs continuously across the full width, no empty vertical band, no seam".

### 검증 절차 (매 컷 필수)
플레이트를 5320×1600 캔버스에 `ALIGN_Y`로 얹고 좌(빨강)·우(파랑) 사각형을 그려
**주 피사체가 사각형 안에 여백까지 두고 들어오는지** 눈으로 확인한다. 딱 맞으면 실패다.

### ★ 세트 일관성은 텍스트로 못 잡는다 — 이미지 레퍼런스로 묶는다
S5~S8c는 고정 카메라에 날씨만 바뀌는 시퀀스인데, 같은 문장으로 따로 생성하니
**매번 다른 절**이 나왔다. 4회를 반복해도 안 됐다.
확정본 S5를 `references:[{type:"image"}]`로 물려서 "카메라·건물 배치·크기는 그대로,
날씨와 빛만 바꿔라"로 지시하니 한 번에 해결됐다. 세트가 있는 컷은 무조건 이 방식을 쓴다.

### 프롬프트에 퍼센트 수치를 쓸 때의 함정
"roof ridge at 58%" 같은 지시는 잘 먹히지만, 한 번은 모델이 그 **수치를 화면에 점선과
라벨로 그려 넣었다**(S15 후보 1장 폐기). 수치 지시를 쓸 때는 `no text, no lettering,
no numbers`를 반드시 함께 넣는다.

### 인물은 "전신"이 아니라 "서 있지 마라"로 지시한다
"full length, head to feet"만으로는 서 있는 인물의 머리가 계속 좌측 스크린 위로 나갔다.
좌측 스크린이 원본 세로의 46~89%만 보기 때문이다.
S4b는 **"NOBODY IS STANDING — 전원 쪼그려·앉아·무릎"**으로 바꾸자 한 번에 해결됐다.

### ★ 우측 파사드에는 꺾이는 선이 있다 (2026-09-11 클라이언트 확인)
우측 파사드는 평면이 아니라 **모서리로 꺾인 두 면**이다. 꺾임선 위치:

| | 값 |
|---|---|
| 파사드 폭 기준 | **58%** |
| 캔버스 x | **3976** |
| 전체 폭 기준 | **74.7%** |

**주 피사체를 이 선에 걸치지 않는다.** 갭(36.1~39.8%)과 함께 **두 개의 금지선**이 생긴 셈이다.
배경·지면·하늘·물·군중은 자유롭게 통과시켜도 되고, 작거나 스쳐 지나가는 인물도 괜찮다.
`build_web.py` 의 `FOLD_R = 0.58` 로 관리하며 보드에 노란 점선으로 표시된다.

### ★ 프롬프트에 "seam / line / 38%" 같은 말을 쓰면 모델이 그려버린다
금지선을 지키게 하려고 "physical seams at 38% and 75%"라고 썼더니
**모델이 그 자리에 실제 세로 선을 그려 넣었다**(S0 후보 1장 폐기).
앞서 퍼센트 수치가 라벨로 찍힌 것과 같은 현상이다. 금지선은 선으로 말하지 말고
**"피사체는 화면 폭 44~70% 사이에 둔다"처럼 배치 범위로만** 지시하고,
`no lines, no borders, no panel divisions, no numbers` 를 부정문에 넣는다.


### 확정 결과
- **25컷 × 3버전 확정** — 22컷은 한판, S14·S15·S16은 좌/우 분할(좌 3안 + 우 3안)
- 사찰 5컷(S5·S6·S7·S8a·S8c)은 4회 반복 끝에 원경 배치로 확정 — 좌측에 전각 온전 + 여백
- S0 안개의 배: 배 전체가 중간 띠(50~78%)에 들어와 돛대 끝까지 우측 화면 안

## 8-1. 한판이 아니라 분할로 가는 컷 — S14·S15·S16

4막 대장간은 **좌우가 서로 다른 사건**이다. 좌측은 어둠 속 대장장이의 타격,
우측은 도가니에 쇳물이 차오르고 쏟아지는 과정이다. 하나의 연속 공간이 아니므로
한판으로 뽑으면 둘 다 어정쩡해진다. **화면별로 따로 생성한다.**

| | 목표 비율 | 생성 | 후처리 |
|---|---|---|---|
| 좌측 | **2:1** | 16:9 (nano-banana는 2:1을 16:9로 스냅함) | 상하 중앙 트림 |
| 우측 | **8:3** | 21:9 | 상하 중앙 트림 (세로 12.5% 손실) |

프레임을 각자 갖게 되므로 **크롭 제약이 사라진다** — 존 규칙도 align도 적용되지 않고,
피사체를 자유롭게 배치할 수 있다. 대신 두 화면의 톤·광원·세트를 맞춰야 하므로
**S14 좌/우를 먼저 확정하고, 그것을 이미지 레퍼런스로 S15·S16을 파생**시킨다.

`shots.json` 에서 `variants` 대신 `variantsL` / `variantsR` 를 쓰고 `"split": true` 를 준다.
렌더러가 자동으로 분할 블록으로 그리고, 각 화면을 클릭하면 그 화면 원본이 받아진다.

### 확정
- S14 좌: 암전 속 대장장이, 백열 쇳덩이만이 광원 / 우: 도가니 바닥에 쇳물이 얕게 고임
- S15 좌: 타격 섬광 폭발 / 우: 쇳물 절반 초과, 표면 껍질이 생겼다 찢어짐
- S16 좌: 거푸집에서 나온 철통들이 모래 위에서 붉게 식음 / 우: 도가니가 기울어 쇳물이 쏟아짐
- 좌 3안 × 우 3안, 세 컷 모두 같은 대장간·같은 도가니

## 9. 세 번째 면 — 바닥
